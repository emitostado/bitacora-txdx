lo que aprendi----
Imagina que estás haciendo un trabajo en equipo y tienes una carpeta con tu proyecto:

Guardar el archivo: es como darle “Guardar” en Word. Los cambios quedan guardados en el archivo que tienes en tu computadora. Git todavía no tiene por qué registrar esos cambios.

Hacer commit: es como tomar una foto de cómo está tu proyecto en ese momento y ponerle una nota, por ejemplo: “Agregué la pantalla de inicio”. El commit queda guardado en el repositorio local de Git, en tu computadora. Sirve para tener un historial de los cambios.

Hacer push: es como subir tus commits a la carpeta compartida de tu equipo (por ejemplo, GitHub). Así, otras personas pueden ver y descargar los cambios. El push lleva tus commits de tu computadora al repositorio remoto.
Guardar → Commit → Push

Archivo en tu computadora → Historial local de Git → GitHub/repositorio remoto

Un ejemplo: editas index.html, lo guardas, haces un commit que diga “Corregí el menú” y finalmente haces push para que ese commit también aparezca en GitHub.

## Lo que entendí el día 1
Hoy aprendí qué es Git y cómo se utiliza para llevar el control de versiones de un proyecto. Git permite guardar los cambios que hago en mis archivos y consultar el historial para saber qué se modificó.

También aprendí qué es GitHub, una plataforma que permite guardar repositorios de Git en línea, compartir proyectos y trabajar en equipo.

Durante el día practiqué algunos comandos básicos de Git:

Comando	¿Para qué sirve?
git init	Crea un repositorio de Git
git status	Muestra el estado de los archivos
git add .	Agrega los cambios para preparar un commit
git commit	Guarda los cambios en el historial
git log	Muestra el historial de commits
git push	Sube los cambios a GitHub
git pull	Descarga cambios desde GitHub
git clone	Copia un repositorio existente

También aprendí el flujo básico de trabajo con Git:

git status
git add .
git commit -m "Descripción de los cambios"
git push

Finalmente, aprendí que los commits sirven para guardar puntos importantes en la historia del proyecto y que es importante escribir mensajes claros para saber qué se modificó.

Conclusión
Hoy aprendí las bases de Git y GitHub y cómo utilizarlos para controlar las versiones de mis proyectos. También practiqué comandos básicos y entendí la importancia de guardar los cambios de manera organizada.
